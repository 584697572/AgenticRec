`KnownUserScorer.from_artifacts` accepts only the exact T08/T09 report, checkpoint SHA256, training data/id-map/split/config/code/seed and dependency versions. BPR-MF scores `user_embedding · item_embedding`; LightGCN scores the corresponding propagated embeddings. `user_id=0` and unknown IDs are rejected. `RoutingScorer` uses those embeddings only when an explicit user ID and `history_authorized=True` are both present. It otherwise routes to the independent `SessionSeedScorer` and records `profile_source=cold_start` or `fallback_popularity` with a reason. The cold scorer computes mean genre Jaccard against liked seeds minus disliked seeds plus `0.01 × normalized log(1 + train popularity)`. It is a T10 policy, not native LightGCN inference; its quality has **not** yet been evaluated. Candidate and seed IDs must be frozen positive model IDs, and known train-rated or anonymous seed items are excluded from recommendation output.

The two real-data T10 traces are generated by `reproduction/scripts/t10_run_upstream_rebuilt.py`: an authorized warm user and an anonymous profile with seeds selected from train-only popularity. They load no valid/test labels, make no remote requests, and run the original `ToolBox → CandidateBuffer → MapTool` in the isolated legacy interpreter. The worker process receives a restricted environment without API credentials. Full scores, IDs and mapped titles are private in `artifacts/upstream_rebuilt/t10_trace_20261006.json`; `reports/upstream_rebuilt/t10_20261006.json` publishes only counts, hashes and pass/fail fields.

This variant is **U1 upstream_rebuilt** under the specification's route B. U0/A1 is the separate original-resource reproduction track. Its unresolved old checkpoint/similarity-matrix ID semantics and redistribution license are not repaired or inferred by U1. T10 does not claim an improved ranking metric or a full original application reproduction.

## T11 extension

`agenticrec.retrieval` and `agenticrec.ranking` are new U1 components for content/CF/popularity recall, RRF and hard constraints. They do not reuse the old gallery's fuzzy/SQL/similarity resources or alter its modules. Their train-positive graph and catalog use the frozen MovieLens1M ID map; the old U0 checkpoint/matrix ID question therefore remains unresolved. The T11 evidence is in `reports/candidate_fusion/t11_20261006.md`.

## T14 extension

`agenticrec.agent.executor` replaces the unsafe plan representation for the new Agent path only. The pinned ToolBox turns the plan list into a dict keyed by tool name and therefore drops earlier repeated calls. The new executor keeps a validated `PlanStep[]`, requires unique `step_id` values, resolves tools through an exact whitelist and validates every step before execution. The original U0/U1 ToolBox remains available as an unchanged comparison; T14 is a project contribution, not an upstream-pristine result. Evidence is in `reports/plan_executor/t14_20261006.md`.

## T15 extension

`agenticrec.agent.state` is a new U1 component. It replaces the upstream memory object's unversioned aggregate sets with immutable `PreferenceState` snapshots and validated `PreferencePatch` events carrying field-level provenance. Explicit feedback outranks inference, model inference cannot write hard constraints, retries are idempotent, conflicts are rejected atomically, and session clearing retains only separately authorized training history. The pinned upstream memory remains unchanged for U0 comparison. T15 validates state semantics only; recommendation quality and Agent task success remain NOT EVALUATED. Evidence is in `reports/preference_state/t15_20261006.md`.

## T18 extension

`agenticrec.evaluation.episodes` is a new project evaluator and does not modify upstream evaluation code. It freezes separate development/test interactive episodes over the independently rebuilt MovieLens1M catalog, stores system-visible and evaluator-only objects separately, rejects target and group leakage, and keeps failed or empty attempts in the denominator. U0's original fuzzy text-hit metrics remain a separate historical result and are not compared directly with this protocol. F/A/O system results are still NOT EVALUATED. Evidence is in `reports/interactive_eval/t18_20261007.md`.

## T19 live execution boundary (2026-10-10)

The new `UpstreamRebuiltTurn` meters a rewritten Plan First JSON prompt and the shared frozen recommendation pipeline, then sends the actual tool-name plan to the existing credential-free `t10_upstream_worker.py`. The worker executes original ToolBox/CandidateBuffer/MapTool, preserving tool-name overwrite behavior. Its ranking tool consumes new mapped scores. This adapts the planner/schema and omits original CRSAgent answer summarization; it is method-level U1, not original prompt/paper reproduction. All systems produce item IDs under the same benchmark contract. U1 latency includes legacy subprocess startup; it cannot isolate planner efficiency alone.

`FaultSchedule` is evaluator-owned and exposes no targets; ranking faults are deterministic local execution fixtures. `variants.py` explicitly removes content or collaborative signals, preserving train-seen filtering. New report generation requires real provider evidence and all failed episodes. All T19 live quality metrics remain NOT EVALUATED until the separately bounded batch runs. Pristine RecAI remains unchanged at the pinned commit.
