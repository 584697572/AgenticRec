## 实现边界

- `ChatAdapter` 只接受严格的 `role/content` 消息，并要求调用方提供 `StrictObjectSchema`。响应必须是 JSON object，缺字段、多字段、类型错误、非有限数和坏 JSON 均失败，不会默默补值。
- 每次真实 transport 尝试在调用前由 `BudgetLedger` 记账。未授权、请求上限或费用上限不满足时，transport 尚未执行就失败。
- `FakeLLM.is_live=false`，因此默认 `allow_paid_api=false` 仍可执行离线 fixture；未知 transport 默认为 live，避免误绕授权门禁。
- 统一重试由 adapter 控制，`sdk_max_retries` 固定为 0 并传给 transport。401 不重试；429、有限 5xx、连接和 timeout 错误才可在额度和 deadline 内有限重试。
- usage 或实际费用不可得时保存 `null` 和原因。真实尝试必须提交正的单次费用上界；账本以费用上界在调用前做 fail-closed 检查。供应商账单硬限额仍不是本地代码能保证的能力。

## Timeout 与 deadline

`per_request_timeout_seconds` 约束一次 provider 调用，传给 transport 用于中止该次网络等待。`round_deadline_seconds` 从一轮开始持续倒计时，覆盖第一次调用、失败耗时、退避和后续重试。每次调用实际拿到的 timeout 是两者较小值。因此单次调用没有超时，并不代表整轮仍有重试时间；整轮 deadline 到期后，下一次尝试不会开始。

这个 adapter 面向能真正执行 timeout 的网络 transport。对于同步 CPU worker，仅让等待方 timeout 不会自动停止底层工作；可靠取消和资源回收仍属于后续运行时故障测试范围，T13 没有据此宣称同步任务已被终止。
