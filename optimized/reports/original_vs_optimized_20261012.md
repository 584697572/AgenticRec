# 原版与优化版：真实对比的指标、现有证据和就绪检查

日期：2026-10-12。当前同条件完整双版本对比：**NOT EVALUATED**。

“原版”指 `original/` 下固定微软源码及其原资源兼容复现，不用 U1 方法适配版或 BPR 替代。“优化版”指 `optimized/` 下个人实现；负结果研究保留，不自动启用。待评测前必须记录实际模型、融合、路由及状态配置和 SHA，不能只写“最新版”。

## 建议主指标

| 维度 | 指标 | 定义与注意事项 |
|---|---|---|
| 推荐命中 | Hit@10 | 有可评测相关目标的用户中，前10个结果至少命中一个的比例。不是所有真实用户会喜欢的概率。 |
| 推荐召回 | Recall@10 | 每位用户的真实相关目标有多少被前10个结果找回，再按用户平均。一个目标时与Hit相同。 |
| 推荐排序 | NDCG@10 | 相关结果越靠前得分越高，按理想排序归一化。建议推荐质量主指标。 |
| 任务执行 | Strict Task Success | 整个任务满足预先定义的数量、身份、年份、类型、排除项、历史反馈等必要条件的比例。任务类别不同须预定义成功规则。 |
| 约束 | 全约束满足率、结果项约束精度 | 分别按任务、结果项计算，必须分别报告；空结果不能自动成为成功。 |
| 对话 | 多轮任务成功、完成所需轮数 | 固定模拟器和停止规则，失败也计入分母。模拟用户结果不能称真实用户满意度。 |
| 消耗 | 请求数、输入/输出token、工具调用数/任务 | 失败请求和重试同样计费计数；总量除以全部任务数，不只成功任务。 |
| 成本 | 元/任务 | 有账单才称实际费用；否则标为token估算，缓存与模型价格单独记录。 |
| 时间 | 端到端延迟p50、p95 | 相同硬件和计时边界，冷启动单列；交错运行减少时段/缓存影响。 |
| 稳定性 | 失败率、超时率、无效工具计划率 | 固定错误分类，保留每条失败记录。 |

覆盖率、热门占比、类型多样性可作为补充，不能用它们代替推荐质量主指标。公开评分只能提供离线相关性代理，不是用户实际满意度。

原论文区分多轮Hit/平均轮数与单轮Recall/NDCG；论文的轮数K和单轮推荐条数K不是同一种K。论文MovieLens单轮表中的Recall@5与20候选排序NDCG@20也不能与本项目全候选NDCG@10直接相比。来源：[原论文§4](https://arxiv.org/html/2308.16505v3)。

## 已有结果能说明什么

1. [T19](benchmark/t19_live_20261010.md)：150条合成任务，三个seed。A始终Agent和O路由版本成功率均81.33%；每seed真实请求190→99，减少47.89%。这是共享接口下的路由对照，**不是原版旧资源系统与最终优化版的对照**。请求减少不能直接当作费用或延迟减少47.89%。
2. 同批U1方法重建版本成功率62.44%，O为81.33%，但U1不是U0原版，且有解析/接口影响，不能写“超越微软原版18.89个百分点”。
3. [固定模型验证](rec_baselines/frozen_model_validation_20261011.md)：BPR/LightGCN测试Hit@10分别65.0594%/65.0943%，NDCG@10分别0.228919/0.227695。配对NDCG差值95%区间跨零，未证明GCN优于BPR。BPR不是微软原版。测试已被历史研究暴露，不是新盲测。
4. [原版45条评测](../../original/reports/a1_multiturn_eval_20261005.md)：真实LLM原评测执行过，但21条目标不可映射及标题年份等问题使0/45不宜作为新版质量提升基线。保留原结果；不能事后删题、改模糊匹配规则再称正式改善。

## 分开做两类对比

### 实际两版本端到端对比

原版保留原工具和资源，优化版保留所选真实配置；统一LLM厂商/模型/输出限制、输入文本、用户历史、推荐条数和评分器。先从预先确认的共同目录构造同题任务，以精确电影身份判定结果，固定类型事实来源及冲突处理规则。明确记录原资源行语义未验证这一限制。

共同目录任务用于测可比较能力；另列目录覆盖和全输入可服务率，不能挑新版会做的题或隐藏目录外失败。身份不明、超时、解析失败全部保留。无可行解任务单独定义正确拒绝条件，不把空列表当合格推荐。需要区分最终回答中的电影与工具实际输出，记录幻觉、遗漏和重复。

先做少量校准任务验证双方入口、会话隔离、评分器与请求计数，校准题不得进入正式测试。之后冻结正式题与配置，交错运行双方，记录原始预测、执行轨迹和用量，再做配对统计。既有历史评价数据如复用，必须标为已暴露；不得称新盲测。

这能回答“当前两个可运行版本在相同任务上哪个更好”，但两边模型/数据本来不同，不能将全部差异归因于LightGCN或路由。旧模型训练集/切分未确认时，离线目标命中只能作描述性结果，不能宣称无泄漏算法收益。

### 控制变量后的算法与Agent对比

若要证明算法收益，按相同可验证训练数据、ID表、候选空间和切分训练上游SASRec方法基线，与BPR、LightGCN及选定优化模型比较；这是统一协议的上游方法复现，不叫作者旧checkpoint或论文完全复现。

若要证明Agent收益，固定同一套数据/推荐工具/LLM，对比上游Agent控制逻辑和个人Agent，并检查接口适配是否改变原逻辑。与上一项分开，避免算法和调度同时改变而无法解释结果。

正式结果按用户/任务配对，报告指标差值及95%置信区间；多个模型seed不是更多独立用户。主指标、抽样、无目标用户处理和允许的调参数据必须先确定。没有新盲测就如实报告，不通过换指标掩盖负结果。
