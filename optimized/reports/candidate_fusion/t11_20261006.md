# T11 multi-route recall, RRF and hard constraints

**Status: PASS for T11 U1 acceptance.** The new `retrieval/` and `ranking/` packages operate only on the frozen T06 MovieLens1M model item IDs. They do not modify upstream RecAI code or the T07 full-universe model evaluation protocol.

The first gate requires a typed `Constraints` object with include/exclude genres, year bounds, excluded item IDs, the seen-item switch and `k`. Genre names are checked against the verified catalog enum; included genres are conjunctive and excluded genres reject any match. Explicit exclusions, train-seen items when authorized, liked seeds and disliked seeds are removed **before** recall. Unsupported requested fields return `MISSING_FIELD`; contradictory conditions return `CLARIFY_CONFLICT`; impossible conditions return `NO_FEASIBLE_ITEMS`. Missing year/genre metadata is not guessed or used to relax a bound. The same gate runs after fusion and is available to T12 for the final rerank.

Content recall uses a deterministic, local TF-IDF index over title tokens, genres and year only. Collaborative recall uses the selected T09 LightGCN score for an explicitly authorized known user, or train-positive item-item co-occurrence for an anonymous liked seed. Popularity counts come from the same verified train-positive graph. Each route contributes at most 100 IDs. RRF scores `sum(1/(60+rank))` over one-based route ranks, deduplicates by frozen item ID and keeps at most 200 IDs. No content cosine, model dot product or popularity count is directly added to another raw score. These are **initial caps**, not hyperparameters selected on test labels.

The unit fixture explicitly reproduces the low-score-mask bug: with scores `{allowed: 1, unwanted: -1e9}` and `k=5`, naive top-k still includes the unwanted item. The hard gate returns only the allowed item with a shortfall of four. Tests also cover all requested `k`, conflicts, unsupported fields, no-solution cases, seen-item authorization, RRF arithmetic, ID validation and recall caps.

The real-data smoke used the frozen selected LightGCN checkpoint and 3,469 candidate IDs. With `Comedy`, `not Horror`, `1990..2000`, one explicit exclusion and one train-only seed, the authorized known-user path had 703 feasible items and fused 191 IDs; the anonymous path had 709 feasible items and fused 197 IDs. Each returned 10 final IDs with **zero** hard-condition violations. Both paths had three sources with 100 candidates each. The structured failure probes returned `MISSING_FIELD`, `CLARIFY_CONFLICT` and `NO_FEASIBLE_ITEMS` as expected. Full item IDs, source ranks and seed details remain in ignored `artifacts/candidate_fusion/t11_trace_20261006.json`; the public [`t11_20261006.json`](t11_20261006.json) contains only counts, statuses and the private trace SHA256. No holdout labels, downloads, LLM calls or remote API requests were used.

The 100/route and 200-union caps bound latency and the number of rerankable items, but also impose a recall ceiling: a relevant item absent from every route cannot be recovered by later reranking.
