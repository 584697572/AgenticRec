## 实现与边界

`PreferenceState` 使用不可变状态保存会话 ID、可选用户 ID、状态版本、硬约束、物品级喜欢/不喜欢、带来源的软偏好、授权训练历史、逐字段证据、待澄清字段和事件账本。每次反馈通过 `PreferencePatch` 校验后原子提交；事件 ID 与内容摘要共同提供重试幂等性，重复事件不追加证据、不提升版本，复用同一事件 ID 提交不同内容会被拒绝。

优先级由来源和轮次共同决定。模型推断不能写入硬约束；显式物品或软偏好会覆盖推断，后续推断不能反向覆盖；同来源内较新轮次优先。较旧的硬字段会被逐字段忽略，但同一 patch 中独立且有效的反馈仍可提交。冲突的包含/排除类型或年份范围返回 `CLARIFY_CONFLICT`，整份 patch 不产生部分写入。

一次“不喜欢物品 25”只写入 `disliked_item_ids:25` 的证据，不改 `exclude_genres`，也不生成类型软偏好。每次有效更新提升 `profile_version`，供后续推荐缓存键失效；幂等重试、被拒绝和全量低优先级更新不会提升版本。

## Session memory 与训练历史

Session memory 是本次对话中由显式反馈或模型推断形成的约束、物品反馈、软偏好和待澄清字段，可由 `clear_session()` 清空。`history_item_ids` 是离线训练/推荐模型允许使用的长期交互历史，创建状态时必须显式传入 `history_authorized=True`；清空 session 会保留这些历史及其 `training_history` provenance。两者不会互相推导，session 中一次否定不会回写训练历史。
