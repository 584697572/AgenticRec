## 评测集冻结

交互评测与推荐模型的全集排序评测保持分离。development 对应 T07 valid cohort，test 对应 T07 test cohort；先从 development 选择 150 个有隐藏正反馈的 warm 用户，再从 test 选择 150 个不与 development 重叠的用户。每个用户只属于一个 split。

每个 split 固定 150 条 episode，其中结构化组件输入 75 条、真实文本输入 75 条、多轮反馈 40 条。场景分布固定为：显式筛选20、个性化20、种子相似20、排除/反馈40、约束冲突15、未知属性15、冷启动10、工具错误10。development/test 的用户组和模板组均无交集；同一文本模板的换电影变体属于同一模板组，不被当成跨 split 的独立模板。

## 指标与完整分母

`episodes.py` 实现 Item Validity、Constraint Precision、Fill@K、Strict Success、Preference Update Accuracy、turn/tool call、p50/p95 latency、token/request、fallback/abstain/clarify/no-solution 统计。

- 缺失 attempt 自动记为 `MISSING_ATTEMPT` 并留在分母。
- 重复、非法、超出目录和违反硬约束的 ID 分别计错，不会在计分前静默删除。
- 可行任务的空输出在 Item Validity、Constraint Precision、Fill@K 和 Strict Success 上均为 0。
- Strict Success 要求状态正确、无非法/违规/重复项、输出不超过 K、达到预注册数量，并命中隐藏接受集合；不可行任务要求正确澄清/无解且输出为空。
- token usage 未知时总 token 保持 `null` 并报告未知 episode 数，不使用估算值冒充实测。
- latency、turn、tool call 和请求数包含失败；p50/p95 使用全 episode 分母。

全空 `ABSTAIN` fixture 已在两个 split 上实跑：每套 150 条中含 120 条可行任务，Fill@K=0、Constraint Precision=0、Strict Success=0，不能靠全拒答刷高结果。该结果只验证评分器防刷规则，不是系统效果。
