## Scope and result

T16 adds the four required decisions, `DIRECT`, `PERSONALIZED`, `AGENT`, and `CLARIFY`, without changing the fixed upstream checkout. Structured requests that already contain enough information use the fixed pipeline directly; authorized users or explicit session seeds use the personalized fixed path. Conflicts, unresolved fields, and low-confidence unparsed inputs clarify. Only inputs whose visible planning-need score reaches the frozen threshold enter the Agent loop.

The Agent loop uses T13's shared budget/deadline ledger and T14's exact-whitelist, full-plan-preflight executor. It validates the final tool result, exposes the exact registered tool schemas to the planner, and allows at most one replan after a retryable tool failure or invalid final result. A second failure stops. Oversized plans fail before any tool side effect.

No separate LLM parser or explanation step is enabled. Text routed to Agent is interpreted and planned in the same metered call; structured fixed routes account for zero LLM calls. If T19 adds a shared natural-language parser for the fixed baseline, that parser must use the same runtime ledger and be reported separately. Every Agent planning or replanning call is already recorded in that ledger. Unknown provider usage remains `null` with its reason rather than becoming zero.

## Why both fixed_pipeline and always_agent are required

`fixed_pipeline` is the strong no-planning baseline with the same recommendation tools, model, constraints, and data. It shows whether dynamic planning adds enough task value to justify its latency, token, and failure surface. `always_agent` holds the LLM, tool pool, and budget constant while sending every request through planning. It shows whether selective routing itself improves the quality/cost tradeoff compared with unconditional Agent use. Comparing only the routed system with the fixed baseline would mix routing value with planning value; comparing only with always-agent would omit the strong deterministic reference. T19 must evaluate F/A/O under the same frozen protocol before any improvement claim.
